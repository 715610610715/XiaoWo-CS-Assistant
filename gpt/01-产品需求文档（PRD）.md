## 一、背景与目标

### 1.1 项目背景

运营商客服中心的标准业务咨询占比高、重复度高。按一个 120 坐席规模的客服中心测算（参考行业公开数据口径），日均咨询约 8000 次，其中套餐、流量、账单、宽带、网络、号码六类标准问题约占 60%。这类问题答案固定，但坐席需要反复解释；月初出账与节假日高峰期排队明显，用户等待时间拉长。

更麻烦的是口径问题。资费、活动、办理条件分散在不同系统和通知里，坐席依赖个人经验和历史话术作答，同一个问题不同人给的答案可能不一样。这类问题时效性强、容错率低，答错一次往往就是一次投诉加一张二次工单。

直接上大模型看起来是最省事的方案，但在资费场景里行不通：大语言模型会顺着用户的话往下说，把不确定的政策讲成确定结论。对客服场景来说，错误答复的代价远高于「这个问题我答不了」。加上咨询内容常带手机号、身份证号、宽带账号，数据不能出内网，外部 API 方案在合规上直接被排除。

### 1.2 问题定义

| 编号  | 问题                   | 现状                            | 影响                   |
| --- | -------------------- | ----------------------------- | -------------------- |
| P1  | 标准业务问题占用大量坐席人力       | 六类标准问题约占咨询量 60%，答案固定却需要人工重复解释 | 人力成本高，高峰期排队明显        |
| P2  | 同一问题答复口径不一致          | 资费与办理条件分散，坐席依赖个人经验和旧话术        | 用户获得的信息不一致，产生投诉和二次工单 |
| P3  | 通用大模型直接生成存在事实性风险     | 模型对不确定政策倾向给出肯定答复              | 错误答复代价高，无法直接用于生产     |
| P4  | 对话含个人敏感信息，公有云方案不满足合规 | 咨询内容常含手机号、身份证号、宽带账号           | 数据不能出内网，排除外部 API 方案  |

### 1.3 产品定位与边界

**定位**：面向运营商标准业务咨询的本地化自助问答工具。用知识库检索保证答案准确，用生成模型提升表达自然度，用规则兜底控制风险；由于为个人demo未上线，整体离线可运行，数据不出内网。

### 1.4 目标

**用户侧目标**：用户用日常说法提一个问题，3 秒内拿到可直接执行的答案——办理入口、查询路径或故障排查步骤。

**业务侧目标**：把标准业务问题从人工承接转为系统承接，同时用统一知识库收敛答复口径，让人工坐席集中在复杂问题和投诉处理上。

**量化目标（本期）：**

| 指标             | 现状  | 本期目标             |
| -------------- | --- | ---------------- |
| 标准问题意图识别 Top-1 | 未统计 | ≥ 95%            |
| 意图识别 Top-3     | 未统计 | ≥ 98%            |
| 关键业务回答错误率      | 未统计 | ≤ 2%（人工抽检 100 条） |
| 检索响应耗时         | 未统计 | ≤ 1 秒            |
| 无模型场景可用性       | 未统计 | 100%             |

> 说明：本期目标是建立评测口径与基线，指标以 41 条知识库、独立测试问法的实测结果为准。知识库扩容后需重新回归，不沿用当前数值。

### 1.5 非目标（本期不做）

| 不做项         | 原因                         | 后续计划     |
| ----------- | -------------------------- | -------- |
| 语音问答        | 需要 ASR/TTS 与打断处理，与本期验证目标无关 | 二期评估     |
| 多轮上下文追问     | 依赖会话记忆与指代消解，本期优先保证单轮准确率    | 二期规划     |
| 工单流转与人工坐席对接 | 需要打通客服系统的权限与工单接口           | 二期       |
| 账号与权限体系     | 单机部署，权限由操作系统账户与文件权限控制      | 二期随后台一起做 |
| 知识运营后台      | 本期知识库以 CSV 文件维护，由运营人员直接编辑  | 二期       |
| 营销与主动推荐     | 与「准确答疑」的产品定位不符，且依赖用户画像数据   | 不列入规划    |

## 二、用户与使用场景

### 2.1 目标用户

| 用户类型       | 使用场景                  | 核心诉求              | 使用入口           |
| ---------- | --------------------- | ----------------- | -------------- |
| 终端用户（联通客户） | 查询套餐、流量、账单，或反馈宽带、网络故障 | 快速拿到可执行答案，不必排队等人工 | App / 网页在线客服窗口 |
| 客服坐席       | 面对标准问题时引用系统答案         | 统一口径，减少重复解释       | 桌面端工作台旁挂使用     |
| 知识运营       | 维护业务问答与同义问法           | 知道哪些问题没有被覆盖       | 知识库文件、评估页      |
| 系统管理员      | 部署与模型配置               | 数据不出内网，可离线运行      | 配置文件与部署包       |

### 2.2 用户故事

| 编号    | 角色    | 我希望          | 以便          | 验收要点                  |
| ----- | ----- | ------------ | ----------- | --------------------- |
| US-01 | 终端用户  | 用日常说法提问就能被理解 | 不用先学会业务术语   | 输入「流量还剩多少」能命中「查询剩余流量」 |
| US-02 | 终端用户  | 一次拿到可直接执行的答案 | 不用在多个入口之间跳转 | 回答包含办理入口或查询路径         |
| US-03 | 终端用户  | 涉及资费时拿到可靠答案  | 不被错误信息误导    | 不确定的问题返回官方核实引导，不编造    |
| US-04 | 终端用户  | 看到相关问题的推荐    | 少打字就能解决后续疑问 | 命中时展示相关问法，点击可直接提问     |
| US-05 | 客服坐席  | 快速定位标准答案     | 减少重复解释的时间   | 展示业务分类与置信度，便于判断是否引用   |
| US-06 | 知识运营  | 知道哪些问题没有被覆盖  | 有针对性地补充知识   | 未命中的问题记录在本地，可回溯       |
| US-07 | 系统管理员 | 在无外网环境下完成部署  | 满足数据合规要求    | 模型与知识库全部本地加载          |
| US-08 | 系统管理员 | 模型缺失时系统仍然可用  | 交付不因模型问题中断  | 自动降级为基础问答模式并明确提示      |

### 2.3 典型场景

**场景 A：标准问题自助（主场景）**

用户想知道当前套餐，但不确定入口在哪。在输入框里输入「我现在办的是什么套餐」，系统检索命中套餐业务知识条目，返回标准答案：可在中国联通 App「服务—查询—我的基本信息」查看，也可拨打 10010。回答下方标注业务分类与置信度，并给出两条相关问法。用户点击「有帮助」，本次问答写入本地记录。

**场景 B：问法不标准**

用户输入「流量还剩多少」。「剩余流量」这个词没有出现在问题原文里，但关键词表中的同义问法覆盖了该表达，检索仍然命中。系统返回查询路径，不因表述口语化而漏答。

**场景 C：知识库未覆盖**

用户询问一个本地知识库没有收录的活动政策。检索最高分低于阈值 0.16，系统判定未命中，返回兜底话术：建议通过中国联通 App 在线客服或 10010 人工核实，并提示以当地最新页面为准。系统不做猜测性回答，该问题被记录进本地日志，供知识运营补充。

**场景 D：模型不可用**

管理员在内网机器上部署，但未放入模型权重。启动后模型预热失败，状态栏显示「基础问答模式」，问答流程自动走检索与兜底。功能可用，只是回答不再是生成文本。管理员补齐权重后重启即可恢复。

### 3.2 优先级判断依据

按「是否阻断主流程」与「是否影响交付可信度」两个维度划分：

- **P0（阻断项）**：缺失则主流程无法闭环或存在业务风险。检索、置信度判定、兜底策略缺一不可——只有检索没有阈值，低分问题会被当成正确答案返回；只有生成没有兜底，模型会编造资费政策。知识库校验与数据脱敏同属 P0，前者决定系统能否正常启动，后者决定数据能否合规使用。
- **P1（体验项）**：不阻断流程，但影响可用性与信任度。相关问法推荐降低用户二次提问成本；评估页是向业务方证明「为什么选这套检索配置」的依据；模型状态提示避免用户误以为系统卡死。
- **P2（增强项）**：系统说明页属于信息补充，不影响功能使用。

实现顺序按依赖链推进：知识库校验 → 检索 → 阈值判定 → 兜底 → 生成 → 评估 → 记录与反馈。

### 3.3 本期范围

本期交付全部 P0 功能与 P1 功能，P2 交付系统说明页。知识运营后台、多轮对话、工单对接、账号体系不在本期。

## 四、业务流程与页面流程

### 4.1 主流程

![业务流程图](assets/业务流程图.svg)

| 步骤  | 动作     | 规则                               |
| --- | ------ | -------------------------------- |
| 1   | 用户提交问题 | 去除首尾空格后判空，空输入直接提示，不进入检索          |
| 2   | 检索候选   | 返回 Top-3 候选及相似度分数                |
| 3   | 置信度判定  | 最高分 ≥ 0.16 判定为命中；低于阈值判定为未命中      |
| 4   | 生成回答   | 仅当 GPT-2 可用时执行；生成异常按空结果处理，不中断流程  |
| 5   | 答案输出   | 生成成功走生成答案；生成失败但命中走知识库答案；未命中走兜底话术 |
| 6   | 记录落盘   | 问题、回答、置信度、业务分类、来源编号写入本地文件        |
| 7   | 界面展示   | 展示回答气泡、业务分类、置信度与反馈按钮             |

### 4.2 异常与降级分支

| 分支     | 触发条件              | 走向                        |
| ------ | ----------------- | ------------------------- |
| 输入为空   | 用户未输入或仅输入空格       | 提示「请输入您的问题」，不写记录          |
| 未命中知识库 | 最高分 < 0.16        | 有模型时先尝试生成，生成失败则兜底；无模型直接兜底 |
| 生成结果为空 | 模型返回空字符串或仅特殊符号    | 回退知识库标准答案                 |
| 模型不可用  | 权重文件缺失、依赖未安装、加载异常 | 全局降级为基础问答模式，状态栏提示，问答流程不变  |

### 4.3 页面流程

```text
启动
 └─ 后台预热模型（不阻塞界面）
     ├─ 成功 → 状态栏「GPT-2 已就绪」
     └─ 失败 → 状态栏「基础问答模式」

主界面（三页签）
 ├─ 智能客服（默认）
 │   ├─ 输入问题 → 生成中 → 回答展示 → 反馈 / 相关问法
 │   └─ 清空对话 → 重置会话区
 ├─ 模型评估
 │   └─ 进入即自动评估 → 重新评估 → 图表与表格刷新
 └─ 系统说明
     └─ 静态展示技术路线与免责声明
```

![智能客服页](assets/线框图-智能客服页.svg)

### 5.2 智能客服页

页面分为顶栏、左侧导航、主对话区三部分。顶栏高 96px，承载产品名与模型状态；左侧导航宽 240px，放置 5 条高频问题与隐私说明；主对话区自上而下为会话标题、消息列表、输入行。

- 左侧高频问题点击后直接填入输入框并发送，用户不必打字；
- 消息列表区分用户与客服两种气泡，客服气泡下方标注业务分类与置信度；
- 输入行包含输入框、「发送问题」主按钮与「清空对话」次按钮；
- 底部提示文案随模型状态变化。

### 5.3 模型评估页

进入页签即自动执行一次评估，展示三套检索配置的对比结果。上方为分组柱状图（Top-1 与 Top-3 双色），下方为指标表格，包含配置名称、Top-1、Top-3、MRR 与测试样本数。「重新评估」按钮用于知识库更新后重新计算。

### 5.4 系统说明页

静态页面，说明技术路线（检索 + 生成 + 兜底）、模块解耦结构，以及资费信息以官方渠道为准的免责声明。页面内容与实现保持一致，不写未落地的能力。

### 5.5 关键交互

| 元素   | 触发     | 反馈                         | 异常处理             |
| ---- | ------ | -------------------------- | ---------------- |
| 发送按钮 | 点击或回车  | 按钮置灰并显示「生成中…」，状态栏切换为「正在回答」 | 重复点击无效；空输入不响应    |
| 回答气泡 | 回答返回   | 展示回答文本、业务分类、置信度与两个反馈按钮     | 请求异常时弹出错误提示并恢复按钮 |
| 相关问法 | 点击标签   | 填入输入框并自动发送                 | 任务进行中时忽略点击       |
| 反馈按钮 | 点击     | 写入本地反馈文件并提示已保存             | 无上一次回答时不响应       |
| 状态胶囊 | 模型预热结束 | 切换为「GPT-2 已就绪」或「基础问答模式」    | 预热失败不影响其他功能      |
| 重新评估 | 点击     | 重新计算并刷新图表与表格               | 数据异常时弹出错误提示      |

## 六、字段与权限说明

### 6.1 知识库字段（data/knowledge_base.csv）

| 字段         | 类型  | 必填  | 约束    | 说明                     |
| ---------- | --- | --- | ----- | ---------------------- |

| answer     | 字符串 | 是   | 非空    | 标准答复                   |

| test_query | 字符串 | 是   | 非空    | 独立测试问法，不得与 question 重复 |

字段校验在启动时执行，任一条目不满足约束即中断启动并给出具体行号。

## 七、异常流程与边界情况

### 7.1 异常处理

| 编号  | 场景      | 触发条件                  | 处理策略             | 用户感知          |
| --- | ------- | --------------------- | ---------------- | ------------- |
| E1  | 输入为空    | 未输入或仅空格               | 不进入检索流程          | 提示「请输入您的问题」   |
| E2  | 知识库缺失   | 文件不存在                 | 启动中断             | 报错并提示文件路径     |
| E3  | 知识库字段缺失 | 表头缺列                  | 启动中断             | 报错并列出缺失字段     |
| E4  | 知识库重复主键 | 两条记录 id 相同            | 启动中断             | 报错并给出行号       |
| E5  | 知识库空值   | id、question、answer 为空 | 启动中断             | 报错并给出行号       |
| E6  | 模型文件缺失  | 权重目录或词表不存在            | 降级为基础问答模式        | 状态栏显示「基础问答模式」 |
| E7  | 依赖未安装   | 未安装推理依赖               | 同上               | 同上            |
| E8  | 生成结果为空  | 模型输出为空或仅特殊符号          | 回退知识库标准答案        | 正常返回答案，无异常提示  |
| E9  | 生成过程异常  | 推理报错或超时               | 回退知识库标准答案；未命中则兜底 | 正常返回答案        |
| E10 | 未命中知识库  | 最高分低于阈值               | 返回兜底话术并记录        | 得到官方渠道引导      |
| E11 | 记录写入失败  | 运行时目录不可写              | 不影响回答展示          | 无感知，日志留痕      |

### 7.2 边界与限制

| 项     | 当前限制              | 说明                    |
| ----- | ----------------- | --------------------- |
| 单轮交互  | 不保留上下文            | 用户需在一句话内说清问题；多轮追问列入二期 |
| 输入长度  | 超长问题按字符截断后检索      | 避免异常输入影响检索稳定性         |
| 语料规模  | 知识库 41 条，覆盖 8 类业务 | 用于验证流程与评测口径，不代表真实业务全量 |
| 并发能力  | 单机单实例             | 多人使用需按部署方案扩容          |
| 政策时效  | 不保证实时性            | 资费类问题一律引导官方渠道核实       |
| 生成可控性 | 无法保证生成内容与知识库完全一致  | 通过阈值与兜底降低风险，生成答案仍需抽检  |

## 八、数据埋点与验收标准

### 8.1 埋点事件

| 事件                        | 触发时机   | 关键字段                      | 用途            |
| ------------------------- | ------ | ------------------------- | ------------- |
| chat_request              | 用户提交问题 | 问题长度、输入方式（手动/点击推荐）        | 统计提问量与输入习惯    |
| chat_reply                | 回答输出   | 耗时、模式（生成/知识库/兜底）、置信度、业务分类 | 计算响应时长与答案来源分布 |
| fallback_triggered        | 判定未命中  | 最高分、问题内容                  | 识别知识盲区，驱动知识补充 |
| suggestion_click          | 点击相关问法 | 被点击问题、来源知识编号              | 评估推荐有效性与覆盖度   |
| feedback_submit           | 提交反馈   | 是否有帮助、来源知识编号              | 计算答案满意度       |
| evaluation_run            | 执行评估   | 配置名称、Top-1、Top-3、MRR、样本数  | 记录方案选型依据      |
| model_ready / model_error | 模型预热结束 | 结果、失败原因                   | 监控部署环境与降级比例   |

埋点沿用现有本地记录文件，不新增外部上报。字段按上表扩展后需同步更新记录写入逻辑。

### 8.2 核心指标

| 指标         | 定义                  | 目标          |
| ---------- | ------------------- | ----------- |
| 意图识别 Top-1 | 独立测试问法中，首位命中正确知识的比例 | ≥ 95%       |
| 意图识别 Top-3 | 前三位包含正确知识的比例        | ≥ 98%       |
| 平均倒数排名 MRR | 正确知识排名的倒数均值         | 记录基线        |
| 兜底率        | 触发兜底话术的问题占比         | 监控，随知识库扩充下降 |
| 反馈好评率      | 「有帮助」占全部反馈的比例       | ≥ 80%       |
| 检索响应耗时     | 检索环节 P95 耗时         | ≤ 1 秒       |
| 降级比例       | 进入基础问答模式的会话占比       | 监控          |

### 8.3 验收标准

| 编号  | 验收项    | 标准                      | 结果                           |
| --- | ------ | ----------------------- | ---------------------------- |
| A1  | 检索准确性  | Top-1 ≥ 95%，Top-3 ≥ 98% | 通过，实测 Top-1 97.6%、Top-3 100% |
| A2  | 方案对比结论 | 完成三套检索配置对比并给出选型依据       | 通过，2-gram 配置 MRR 0.988 最优    |
| A3  | 未命中处理  | 未命中问题均返回兜底话术，不输出业务结论    | 通过，逻辑已验证                     |
| A4  | 无模型可用性 | 移除模型后系统可正常问答            | 通过，自动降级，功能可用性 100%           |
| A5  | 数据合规   | 全流程无外部网络请求              | 通过，模型与知识库本地加载                |
| A6  | 记录完整性  | 每次问答与反馈均可落盘且可读          | 通过                           |
| A7  | 自动化测试  | 单元测试全部通过                | 通过，6/6                       |
